# Reference Wiki

Deep notes on products and systems that can inform Menoteam. These pages are research notes, not product requirements.

Last checked: 2026-06-29.

## Reading Lens

Menoteam should stay light, elegant, and meta. The durable layer is:

```text
human philosophy -> goal formation -> autonomous work -> trace -> evaluation -> reflection
```

Each reference is useful only insofar as it helps one of those links become more real without turning Menoteam into a thick control plane.

## References

| Reference | Main Lesson | Main Trap |
|---|---|---|
| [Paperclip](paperclip.md) | Model autonomy as operated work with goals, budgets, heartbeats, governance, and audit. | Org chart-first thinking can turn a person's philosophy into bureaucracy. |
| [OpenHands Agent Canvas](openhands-agent-canvas.md) | Keep the control surface separate from execution backends. | Becoming an agent launcher instead of a judgment framework. |
| [OpenHands Software Agent SDK](openhands-sdk.md) | Clean execution primitives: agent, conversation, tool, workspace, server. | Execution APIs do not define meaning, taste, or standards. |
| [Hermes Agent](hermes-agent.md) | A personal agent can learn through skills, memory, gateways, cron, and backends. | Self-improvement can become agent-centric instead of framework-centric. |
| [Hermes MoA](hermes-moa.md) | Many advisory perspectives can improve judgment while one actor remains accountable. | Multi-model reasoning does not create persistent philosophy by itself. |
| [Hermes Goal Loop](hermes-goal-loop.md) | Durable goals need continuation, judging, waiting, and evidence contracts. | Task-level persistence is not the same as human-level meaning. |
| [Paxel](paxel.md) | Agent transcripts reveal how a builder steers, judges, plans, and ships. | Retrospective analytics do not automatically improve future autonomous work. |
| [GBrain](gbrain.md) | Durable memory, retrieval, code indexing, and MCP serving are useful substrate. | Memory is not the product philosophy. |

## Current Synthesis

Menoteam should borrow operational seriousness from Paperclip, backend modularity from OpenHands, learning and goal continuation from Hermes, behavior-derived profiling from Paxel, and memory substrate from GBrain.

It should avoid copying the visible form of any one of them. The product should not start as an org chart, coding dashboard, SDK, memory app, or personal analytics report. Those are possible connectors or views. The deeper object is an operating philosophy that can guide autonomous work over time.
